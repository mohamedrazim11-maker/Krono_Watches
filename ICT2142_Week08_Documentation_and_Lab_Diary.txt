1. DATABASE SCHEMA (MILESTONE 1)
================================================================================

1.1 Table Relationships:
--------------------------------------------------------------------------------
The database is the single source of truth for the store. All permanent data
is saved in the database:
1. One User can have Many Orders (1 : M).
2. One Order can have Many Order Items (1 : M).
3. Each Order Item points to One Product (M : 1).
4. Stock decreases after an order is confirmed.

Entity-Relationship Layout:
+---------------------+              +-----------------------+
|        USERS        | 1          M |        ORDERS         |
+---------------------+--------------+-----------------------+
| PK id               |              | PK id                 |
|    full_name        |              | FK user_id            |
| UK email            |              |    customer_name      |
|    password_hash    |              |    customer_email     |
|    role             |              |    total_amount (LKR) |
|    created_at       |              |    status             |
+---------------------+              |    created_at         |
                                     +-----------------------+
                                                 | 1
                                                 | contains
                                                 | M
+---------------------+              +-----------------------+
|      PRODUCTS       | 1          M |      ORDER_ITEMS      |
+---------------------+--------------+-----------------------+
| PK id               |              | PK id                 |
|    name             |              | FK order_id           |
|    brand            |--------------| FK product_id         |
|    price (LKR)      |              |    quantity           |
|    stock_qty        |              |    unit_price (LKR)   |
|    image_url        |              +-----------------------+
|    is_active        |
+---------------------+

1.2 Table Definitions:
--------------------------------------------------------------------------------
1. users: Stores user accounts, hashed passwords, contact info, and role ('admin' | 'customer').
2. products: Stores watch details, brand, price in LKR, stock quantity, and active status.
3. orders: Stores customer orders, delivery info, recalculated total in LKR, status, and date.
4. order_items: Stores individual items in each order with product ID, quantity, and unit price.

================================================================================

2.1 Connecting Products to the Database (Milestone 2):
--------------------------------------------------------------------------------
- Replaced static JavaScript arrays with database queries.
- GET /api/products loads all active products.
- GET /api/products/[id] loads the selected product details by ID.
- Checkpoint: Refreshing the catalog page (/catalog) or product details page keeps
  showing live products loaded from the database.

2.2 Saving Orders during Checkout (Milestone 3):
--------------------------------------------------------------------------------
When a customer clicks checkout:
1. Validate Cart: The server checks product IDs, prices, and available stock in the database.
2. Recalculate Total on Server: The server does not trust prices sent by the browser:
   Total = Sum(Database Price * Quantity) - Discount
3. Create Order: Creates a record in the orders table.
4. Create Order Items: Saves each item into the order_items table linked to the order ID.
5. Update Stock: Subtracts the purchased quantity from stock_qty in the database.
6. Return Result: Returns the order confirmation and order ID (e.g. KR-1031) to the customer.

3. SIMPLE ADMIN DASHBOARD STRUCTURE (MILESTONES 4 & 5)
================================================================================

The Admin Dashboard is organized into three simple sections:

3.1 Section 1: Summary Cards (Slide 9):
--------------------------------------------------------------------------------
Located at /admin:
- Products (128): Total active products in the store.
- Orders (24): Total customer orders placed.
- Low Stock (7): Products with 5 or fewer items remaining in stock.
- Database Status (Connected ✓): Shows that the database is connected and active.

3.2 Section 2: Products & Inventory (Slide 10):
--------------------------------------------------------------------------------
Admins can manage products with simple actions:
- Create: Click "Add Product" to add a new watch with name, price, stock, and image.
- Read: Search and view all products in a clear table with ID, price, and stock.
- Update: Use '+' and '-' buttons to quickly change stock, or open the edit modal to update details.
- Delete / Deactivate: If an item was already ordered by customers, it is safely
  soft-deleted (is_active = false) so past order records remain intact.

3.3 Section 3: Orders & Status Updates (Slide 11):
--------------------------------------------------------------------------------
Admins can track customer orders in an order table:
- Columns: Order ID | Customer | Items | Total (LKR) | Status | Action
- Simple Status Flow:
  Pending  ──►  Paid  ──►  Processing  ──►  Shipped  ──►  Completed
- Admins can change order status with one click, and the change updates the database immediately.

5. SECURITY & ADMIN PROTECTION (MILESTONE 4)
================================================================================

5.1 Simple Access Check Flow:
--------------------------------------------------------------------------------
User visits /admin
       │
       ▼
Is user logged in? ──No──► Redirect to /login
       │ Yes
       ▼
Is role == "admin"? ──No──► Redirect to / (Access Denied)
       │ Yes
       ▼
Show Admin Dashboard

- Middleware Check (frontend/middleware.ts): Runs on every /admin request. If the user
  is not an admin, they are redirected immediately.
- Page Guard (frontend/app/admin/layout.tsx): Confirms admin status in the browser so
  non-admin users cannot see cached admin pages.
- API Route Guard (frontend/lib/server/auth.ts): Rejects unauthorized requests with HTTP 401 or 403.

6. DEBUGGING LOG (TWO PROBLEMS SOLVED)
================================================================================

6.1 Problem 1: Middleware crashed when checking login tokens
--------------------------------------------------------------------------------
- What happened: When protecting /admin routes in Next.js middleware, importing
  the Node.js jsonwebtoken library caused errors because Next.js Edge Middleware
  runs in a lightweight environment that does not support Node.js crypto.
- How it was fixed: We wrote a simple, lightweight token decoder directly inside
  middleware.ts that safely reads the user role (admin vs customer) without needing
  external libraries.

6.2 Problem 2: Browser could send incorrect order totals
--------------------------------------------------------------------------------
- What happened: The checkout page originally calculated the order total in
  JavaScript and sent it to the backend. A user could alter the JavaScript and
  submit an incorrect price.
- How it was fixed: We updated the backend so it never trusts prices sent by the
  browser. The server reads the verified prices directly from the database,
  recalculates the subtotal, checks available stock, and saves the verified total.
